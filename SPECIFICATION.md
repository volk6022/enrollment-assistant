## В двух словах

Существующий сервис отвечает на вопрос последовательно: транскрибация → RAG → генерация →
синтез → воспроизведение. Задержки складываются, диалога нет.

Новый ведёт диалог: слушает по ходу речи, начинает говорить до того, как дописал ответ,
может быть перебит и может перебить сам, а главное — сначала выясняет, чего человек хочет,
и только потом лезет в базу знаний.

Это переписывание. Из текущего кода переносится RAG-пайплайн, нормализация текста перед TTS
и инвентарь GUI.

## Решения, которые уже приняты

Каждое опирается на замер или на прямое указание заказчика. Менять — только с новым замером.

| Решение | Почему |
|---|---|
| Монолит на asyncio, единственный внешний процесс — llama-server | GIL не блокер: разрыв loop 8–36 мс в POC |
| Whisper large-v3-turbo **на GPU** | на CPU RTF 5.24 при нужном < 0.3; настройками не лечится |
| Silero v5.5 **на CPU** | RTF 0.066 достаточно, VRAM освобождается |
| Эмбеддер и реранкер **на GPU**, GGUF Q8_0 | переезд на CPU закрыт (реранкер ×122); Q8_0 неразличим от fp16 (t=0.35) |
| `RAG_TOP_K = 10` | сетка 1200 тестов: значимый прирост против k=5, k=15/20 не окупают префилл |
| Ризонинг гасится **предзаполненным `<think></think>`** | единственный работающий способ: 0.075 с против 2.5 с |
| Решения агента — **сырой `/completion` + `json_schema`** | на chat-эндпоинте это даёт HTTP 400 |
| Классификатор перебивания — **событийный, не опрос** | опрос в цикле замедляет генерацию ×2.09 |
| `-np 2 -c 32000` | под пару «стрим + одно разовое решение» |
| llama-server **не в docker** | решение заказчика: в проде инференс-сервер чужой |
| GUI — React + Vite | решение заказчика; функциональный паритет по `gui-spec-current.md` |
| Модели **не скачиваются** сервисом, кроме whisper и silero | решение заказчика; ссылки в README |

## Порядок работы

1. Прочитать `spec.md` и `plan.md` целиком. В `plan.md` §4 — три ограничения, которые нельзя
   вывести из документации llama.cpp и которые ломают реализацию, если их не знать.
2. Взять задачу из `tasks.md`, прочитать контракты, на которые она ссылается.
3. Спеки — источник правды. Расхождение реализации со спекой — баг реализации;
   расхождение спеки с замером в `streaming-research-findings.md` — повод остановиться
   и сказать, а не выбирать самому.
4. Меняется логика диалога — сначала правится `dialogue.qnt`, прогоняются `verify.ps1` и
   `reachability.ps1`, и только потом код.

## Проверка формальной модели

```powershell
.\specs\formal\verify.ps1        # инварианты  → «все инварианты проверены»
.\specs\formal\reachability.ps1  # достижимость → «все состояния достижимы»
```

Оба скрипта сами поднимают сервер Apalache. Обход через `--server-endpoint` нужен потому, что
`quint verify` запускает Apalache через `.bat`, а Node 20+ отказывается спавнить `.bat` без
шелла (следствие исправления CVE-2024-27980) и падает с `EINVAL spawn`.

Модель уже нашла одну дыру в требованиях: перекрытие речи поверх короткого хвоста реплики не
было описано ни одним правилом, и агент зависал с недоигранным ответом. Закрыто требованием
FR-15 — договариваем хвост без обращения к LLM.
