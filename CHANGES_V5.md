# v5 — intent-aware retrieval, safer answers, project cleanup

## Что улучшено по качеству ответов

- Добавлен канонический слой `question_intent`:
  - `documents`
  - `deadlines`
  - `apply`
  - `contacts`
  - `exams`
  - `min_scores`
  - `without_ege`
  - `benefits`
  - `eligibility`
  - `normative`
- Разные пользовательские формулировки теперь приводятся к одному смысловому классу.
- Для рискованных intents (`min_scores`, `without_ege`, `benefits`) добавлены отдельные профили поиска и защитные правила.

## Что улучшено в RAG

- Добавлен более жесткий pre-filter по смыслу вопроса.
- Для `min_scores` штрафуются фрагменты про:
  - индивидуальные достижения
  - диплом с отличием
  - ГТО
  - дополнительные баллы
- Для `apply` и `documents` исключаются побочные документы вроде сроков хранения и ВВК.
- Для `contacts` ответы идут только из `contacts.json`.
- Поиск больше не использует старые PDF-коллекции и не опирается на PDF-контур.

## Что улучшено в генерации

- LLM получает не только профиль вопроса, но и `question_intent`.
- Усилены запреты на смешение:
  - минимальных баллов ЕГЭ и индивидуальных достижений
  - льгот и платных мест
  - поступления без ЕГЭ и общих норм без процедурного акта
- Добавлены post-check guards для `min_scores`, `without_ege`, `benefits`, `organizational`.

## Что улучшено в диалоге

- Уточнения стали еще более адресными.
- Для `min_scores` и `exams` при нехватке данных система старается задать только одно полезное уточнение по уровню обучения.
- Для answer-first intents уточнение по-прежнему не навязывается, если есть шанс дать безопасный общий ответ.

## Очистка проекта

Удалено старое PDF-наследие:
- `data/pdf/`
- `data/pdf_versions/`
- `backend/app/indexer.py`
- `backend/scripts/index_pdf.py`
- лишние PDF-переменные из `docker-compose.yml`
