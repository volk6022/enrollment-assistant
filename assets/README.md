# assets/

Монтируется в backend-контейнер как `/app/assets` (см. `docker-compose.yml`,
`GREETING_AUDIO_PATH` в `.env.example`).

## `greeting.wav`

Предзаписанное приветствие (FR-01). Требуется:

- моно, 16 кГц (тот же формат, что и остальной звуковой тракт — `AUDIO_SAMPLE_RATE`
  в `.env.example`); при другом sample rate — привести к 16 кГц перед тем, как класть
  сюда;
- содержит **реальную речь**, не тишину и не синтетический шум — `WhisperWorker`
  использует этот же файл для прогрева CUDA (`backend/stt/whisper_worker.py`), и на
  тишине/шуме прогрев не отрабатывает (118–121 мс стопор на первом реальном запросе
  вместо 1.5–5.6 мс, см. `plan.md` §2 «Тишина прогревом не является»).

**Обновление (найдено позже, при сквозном прогоне A-13 для T-11):** класть этот
файл вручную больше не обязательно. `backend/ws/session.py::ensure_greeting_audio`
(T-09, приземлился уже после того, как эта заметка была написана) сам
синтезирует `greeting.wav` через Silero при первом старте backend, если файла
по `GREETING_AUDIO_PATH` нет — идемпотентно, проверено вживую (лог
`greeting_audio_generated`). Файл ниже описывает случай, когда хочется
**заменить** сгенерированный на живую дикцию — тогда действуют требования к
формату ниже; для этого положить сюда `greeting.wav` вручную по-прежнему можно,
он не будет перезаписан (генерация условна: `if path.exists(): return`).

Путь внутри контейнера читает `GREETING_AUDIO_PATH=/app/assets/greeting.wav`
(`.env.example`) — переименовывать нельзя без правки `.env`.
