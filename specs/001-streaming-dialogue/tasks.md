# Задачи: потоковый диалоговый ассистент

Требования — [`spec.md`](./spec.md) · архитектура — [`plan.md`](./plan.md) ·
контракты — [`contracts/`](./contracts/)

Разбивка сделана так, чтобы задачи одной волны не трогали одни и те же файлы. Каждая задача
называет свои файлы, свои требования и свою проверку.

**Правило для всех задач.** Спеки — источник правды. Если реализация расходится со спекой,
это баг реализации; если спека противоречит замеру в
[`docs/streaming-research-findings.md`](../../docs/streaming-research-findings.md) — остановиться
и сказать, а не выбирать самому.

## Волна 1 — фундамент (параллельно, файлы не пересекаются)

### T-01 · Конфигурация и каркас
**Файлы:** `backend/config.py`, `backend/app.py`, `.env.example`
**Требования:** FR-32, NFR-06
Pydantic-settings: **единственное** место чтения `.env` в проекте. Все переменные из
`.env.example`, с типами и валидацией. FastAPI-приложение: `/ws/dialogue`, `/health`,
`/metrics`, сборка зависимостей, graceful shutdown. `/health` проверяет реальную достижимость
трёх llama-эндпоинтов, а не «процесс жив».
**Проверка:** старт с пустым `.env` даёт внятный список недостающих переменных, а не
`KeyError`.

### T-02 · Аудио: кольцо, часы, VAD
**Файлы:** `backend/audio/{ring,clock,vad}.py`
**Требования:** FR-02, FR-05, FR-06, FR-09 · контракт [`memory.md` §1–3](./contracts/memory.md)
`AudioRing` (60 с, запись на loop под `Lock`, `snapshot()` возвращает копию), `SessionClock`
на `time.monotonic()`, `VadGate` с прероллом `VAD_PREROLL_MS`.
**Проверка:** unit-тест на преролл — речь, начатая за 250 мс до срабатывания VAD, попадает в
окно транскрибации целиком.

### T-03 · Клиент llama-server
**Файлы:** `backend/llm/{client,prompts,schemas}.py`
**Требования:** FR-10 · контракт [`llm.md`](./contracts/llm.md) целиком
Два пути вызова, ни одного третьего. `stream_answer` с предзаполненным `<think>\n\n</think>`;
`decide` через сырой `/completion` + `json_schema`. `cache_prompt: true` везде. Семафор на 1
для конкурентных `decide` (`plan.md` §4.4).
**Проверка — контрактные тесты против живого сервера, не моки:**
(а) в потоке `stream_answer` нет `<think>`, TTFT < 0.3 с;
(б) `decide` возвращает валидный по схеме объект и не содержит рассуждения;
(в) повторный вызов с тем же префиксом переиспользует кэш (`prompt_tokens` падает на порядок).
§4.2 замеров показывает, что «правильный» по документации вызов даёт HTTP 400 — мок это
пропустит, живой сервер нет.

### T-04 · Перенос RAG на GGUF-энкодеры
**Файлы:** `backend/rag/`
**Требования:** §6 плана
Перенести существующий `rag/`, заменить бэкенды энкодеров на llama-server GGUF Q8_0,
`RAG_TOP_K=10`. Флаги отключения кэша обязательны:
`--no-cache-prompt -cram 0 -ctxcp 0 -cpent -1`.
**Проверка:** прогон по всем 5856 чанкам индекса без HTTP 500 (без флагов сервер умирал
примерно на 784-м тексте).

### T-05 · STT и TTS воркеры
**Файлы:** `backend/stt/whisper_worker.py`, `backend/tts/{silero_worker,text_normalize}.py`
**Требования:** FR-04, NFR-03, NFR-04 · [`plan.md` §2, §3.3, §3.4](./plan.md)
Раздельные однопоточные пулы. Whisper на CUDA, прогрев **из воркер-потока**. Троттлинг:
≤ `STT_PARTIAL_MAX_HZ`, не более одного прогона в полёте, при просрочке такт пропускается,
а не копится. Silero на CPU, вызов только через `run_in_executor`. `text_normalize.py`
переносится из `services/voice-gateway/app/` как есть.
**Проверка:** разрыв event loop < 50 мс под одновременной нагрузкой STT+TTS (NFR-04).

## Волна 2 — диалог (после волны 1)

### T-06 · Память диалога
**Файлы:** `backend/dialogue/{memory,models}.py`
**Требования:** FR-12, FR-16, FR-18, FR-19, FR-20 · контракт [`memory.md`](./contracts/memory.md)
`DialogueTurn`, `DialogueState`, `Draft`, `DialogueMemory`. Сборка переплетённой истории из
таймингов whisper и оффсетов воспроизведения; перекрывающиеся интервалы сохраняются как есть.
Буфер транскрипта 5000 символов, усечение **с головы**. Сериализация в промпт с явной
пометкой перекрытий.
**Проверка:** unit-тест на перекрытие — реплика собеседника, начавшаяся до конца реплики
агента, сериализуется с пометкой «поверх» и не сдвигает границы.

### T-07 · Автомат
**Файлы:** `backend/dialogue/{machine,nodes}.py`
**Требования:** FR-03, FR-07, FR-08, FR-13, FR-15, FR-25, FR-26 ·
модель [`dialogue.qnt`](../formal/dialogue.qnt), диаграмма [`STATE_MACHINE.md`](../formal/STATE_MACHINE.md)
LangGraph, нода на каждое из **восьми** состояний, включая `ended`. Переходы через
`add_conditional_edges` (у `add_edge` нет параметра `condition`). Каждое ребро = ровно одно
`action` из `.qnt`, имя метода совпадает с именем действия.
**Проверка:** таблица соответствия «действие в `.qnt` → ребро в графе», полная в обе стороны.
Тест на FR-08: после решения «слушать дальше» `turnLen` не обнулился. Тест на FR-15:
перекрытие поверх хвоста ≤ `TAIL_MIN` не вызвало LLM.

### T-08 · Сценарии
**Файлы:** `backend/dialogue/scenarios.py`, `dialogue/scenarios.yaml`
**Требования:** FR-21…FR-24
Загрузчик и матчер. Словарь допустимых условий и действий — закрытый и задокументированный
в самом YAML. Загрузчик **падает на старте** при ссылке на неизвестное условие или действие:
молча проглоченная опечатка в YAML означает сценарий, который никогда не сработает.
Единственный источник `intent` и `confidence` — `IntentDecision`
([`llm.md` §4.3](./contracts/llm.md)); других «оценок намерения» в системе нет.
**Проверка:** тест на битый YAML — сервис не стартует и называет строку.

### T-09 · Оркестрация сессии
**Файлы:** `backend/ws/session.py`
**Требования:** FR-01…FR-03, FR-09…FR-17 · контракт [`websocket.md`](./contracts/websocket.md)
Склейка: сокет → кольцо → VAD → STT → автомат → RAG/LLM → TTS → сокет. Событийный гейт
перебивания (FR-17): один вызов `decide` по событию VAD, никакого опроса в цикле. Отмена
генерации без коммита в память (FR-12).
**Проверка:** приёмочные A-01…A-11 на заранее записанных аудио.

## Волна 3 — оболочка

### T-10 · GUI
**Файлы:** `gui/`
**Требования:** FR-27…FR-29 · baseline [`gui-spec-current.md`](../../docs/gui-spec-current.md),
контракт [`websocket.md`](./contracts/websocket.md)
React + Vite. Захват микрофона через `AudioWorklet` (не `ScriptProcessorNode` — он устарел),
потоковое воспроизведение с немедленным сбросом очереди по `audio.flush`.
Из baseline переносится **всё**: элементы управления (§2), поля вывода (§3), состояния UI
(§4), «Технические данные» с развёрнутым JSON (§6), микрофон и аудио (§7), тема по
`prefers-color-scheme`.
**Проверка:** приёмка A-12 — пройти по таблицам §2 и §3 `gui-spec-current.md`, каждый элемент
на месте и работает. Сброс очереди по `audio.flush` < 200 мс.

### T-11 · Docker и запуск
**Файлы:** `docker-compose.yml`, `backend/Dockerfile`, `gui/Dockerfile`,
`scripts/serve-models.{ps1,sh}`, `README.md`
**Требования:** FR-30, FR-31 · [`plan.md` §11](./plan.md#11-docker)
В compose — только `backend` и `gui`. llama-server **не в compose**: поднимается на хосте
скриптом, backend ходит через `host.docker.internal` (на Linux — `extra_hosts`). GPU
пробрасывается в backend. Веса монтируются volume'ом из `MODELS_DIR`, **не** скачиваются.
README: ссылки на веса (места под них оставить, ссылки даёт Иван), порядок запуска, минимум
VRAM.
**Проверка:** приёмка A-13 — чистый клон, `.env`, `up -d`; отсутствие весов даёт внятную
ошибку, а не стек-трейс.

### T-12 · Тесты и телеметрия
**Файлы:** `tests/`, `backend/telemetry.py`
**Требования:** NFR-01…NFR-05 · [`plan.md` §12](./plan.md#12-тестирование)
Пять уровней из плана. Логирование в JSON: каждое решение LLM с `reason` и латентностью,
каждый переход автомата, тайминги по компонентам. Блок `decisions` в `meta`
([`websocket.md` §3.6](./contracts/websocket.md)).
**Проверка:** прогон приёмочных A-01…A-13 одной командой.

## Финальная проверка

Отдельный агент, который **не писал код**. Порядок:

1. Прогнать `specs/formal/verify.ps1` и `reachability.ps1` — модель по-прежнему чиста.
2. Сверить `backend/dialogue/machine.py` с `dialogue.qnt` **по каждому действию**: 25 действий
   модели против рёбер графа, соответствие в обе стороны. Считать по реестру, который
   реально скармливается в `add_conditional_edges`, а **не** по
   `compiled_graph.get_graph().edges`: LangGraph схлопывает условные рёбра с одинаковой
   парой (source, target), и оттуда молча пропадают четыре действия.
3. Проверить, что путей вызова LLM ровно два и оба соответствуют
   [`llm.md`](./contracts/llm.md): найти любой `POST` к llama-server мимо `LlamaClient`.
4. Проверить троттлинг STT: в полёте не больше одного прогона, частота не выше
   `STT_PARTIAL_MAX_HZ`.
5. Проверить, что `decide` не вызывается ни из какого цикла или таймера — только по событию.
6. Проверить, что `.env` читается **только** в `config.py`: `os.environ` и `getenv` в
   остальном коде — нарушение FR-32.
7. Проверить пулы: три раздельных, по одному воркеру, состояние мутируется только на loop.
8. Прогнать приёмочные A-01…A-13, доложить фактические цифры против NFR-01…NFR-05.

Отчёт — что подтверждено замером, что не проверено и почему. Формулировки «выглядит
корректно» не принимаются.
