# Контракт: аудио-буферы и память диалога

Реализация — `backend/audio/`, `backend/dialogue/memory.py`.
Требования: [`../spec.md`](../spec.md) FR-05, FR-09, FR-12, FR-16, FR-18…FR-20.

Это самая недооценённая часть системы. Речь двух участников **перекрывается**, whisper
отдаёт тайминги относительно куска аудио, а не сессии, а наше собственное аудио может быть
оборвано на середине. Если не собирать историю аккуратно, LLM получает последовательность,
которой не было — и рассуждает над вымыслом.

---

## 1. Единая ось времени

Всё измеряется в **миллисекундах от `t0`** — момента открытия сессии (`audio/clock.py`).

```python
class SessionClock:
    t0: float                    # time.monotonic() на старте сессии
    def now_ms(self) -> int: ...
```

`time.monotonic()`, не `time.time()`: перевод системных часов не должен рвать историю.

Единая ось — то, что делает возможным пункт FR-18. Тайминги whisper пересчитываются в неё
прибавлением оффсета окна; наше воспроизведение попадает в неё напрямую.

## 2. Кольцевой аудио-буфер

```python
class AudioRing:
    """PCM16 моно 16 кГц, ёмкость AUDIO_RING_SECONDS (по умолчанию 60 с)."""

    def append(self, pcm: bytes, at_ms: int) -> None:
        """Только с event loop. Держит threading.Lock: запись — read-modify-write."""

    def snapshot(self, from_ms: int, to_ms: int | None = None) -> np.ndarray:
        """Возвращает КОПИЮ. В воркер-поток уходит только результат этого метода."""
```

Правила, невыполнение которых даёт гонки или регрессию латентности:

- Пишется **непрерывно** с открытия сессии и **никогда** не останавливается — ни в
  `Speaking`, ни в `Closing`, ни во время решений LLM (FR-09).
- `append` вызывается только с event loop. `snapshot` возвращает `np.concatenate(...)` —
  копию; воркер-поток никогда не видит мутирующий объект, поэтому гонок нет by construction.
- Кольцо — **не** память диалога. Его задача: восстановить начало речи, корректно поймать её
  конец и пережить перебивание. История диалога живёт отдельно (§4).
- Переполнение затирает старое молча. 60 с достаточно: единственный потребитель прошлого —
  преролл VAD и текущее окно STT.

## 3. VAD и отметка начала речи

```python
class VadGate:
    def feed(self, pcm: bytes, at_ms: int) -> VadEvent | None
    def notify_agent_speaking(self, speaking: bool) -> None
```

События: `SpeechStarted(speech_start_ms)`, `SpeechEnded(end_ms)`, `Overlap(duration_ms)`.

`notify_agent_speaking` обязателен, потому что `VadGate` видит **только микрофон**, а
перекрытие по определению требует знать, говорит ли в этот момент агент. Оркестрация сессии
(T-09) дёргает его при старте и остановке воспроизведения. Без этого вызова `Overlap` никогда
не сработает, и перебивание перестанет распознаваться — молча, без единой ошибки в логе.

Ключевая деталь — **преролл** (FR-05). Детекция опаздывает; поэтому:

```
speech_start_ms = момент_срабатывания_ms - VAD_PREROLL_MS      # по умолчанию 300
```

Транскрибация читает кольцо начиная с `speech_start_ms`, а не с момента срабатывания.
Без этого первое слово реплики систематически теряется — приёмка A-01 ловит это прямо.

- Конец хода — `VAD_SILENCE_END_MS` (500 мс) непрерывной тишины (FR-06).
- Перекрытие: когда агент в `Speaking` и VAD говорит «речь», счётчик перекрытия растёт.
  По достижении `DIALOGUE_BARGE_IN_OVERLAP_S` **и** при остатке аудио
  > `DIALOGUE_BARGE_IN_MIN_TAIL_S` испускается одно событие → один вызов `decide` (FR-17).
  Не по таймеру, не в цикле.
- VAD (silero-vad) работает на CPU и дёшев. Он и есть тот «не-LLM гейт», который защищает
  GPU от лишних вызовов классификатора.

## 4. Модель истории диалога

```python
@dataclass
class DialogueTurn:
    role: Literal["user", "agent"]
    text: str
    start_ms: int
    end_ms: int
    # только для role="agent":
    voiced_fraction: float | None   # 0.0–1.0, доля реально прозвучавшего
    is_partial: bool                # прервали на середине (FR-16)
    # только для role="user":
    stt_confidence: float | None
```

```python
@dataclass
class DialogueMemory:
    turns: list[DialogueTurn]        # по возрастанию start_ms; интервалы МОГУТ пересекаться
    transcript_buffer: str           # <= 5000 символов, усечение с головы
    chunk_timings: list[tuple[int, int]]   # тайм-коды кусочков; содержимое чанков НЕ хранится
```

### Откуда берутся границы

| | `start_ms` | `end_ms` |
|---|---|---|
| реплика собеседника | `speech_start_ms` (с прероллом) | момент `SpeechEnded` |
| реплика агента | момент отправки первого PCM-чанка в GUI | старт + **фактически отданная** длительность |

Для агента считается именно отданное аудио, а не длина синтезированного файла. При уступке
эти числа расходятся — и это ровно та разница, которую хранит `voiced_fraction`.

### Перекрытия

Интервалы соседних `turns` **могут пересекаться**, и это не ошибка сортировки, а сам смысл
дуплексного диалога. Реализация не имеет права «чинить» перекрытие, раздвигая границы.

При сериализации в промпт перекрытие отмечается явно, чтобы модель видела, что реплики шли
одновременно:

```
[00:12.3–00:19.8] агент: Для поступления понадобятся паспорт, аттестат и…
[00:16.1–00:18.4] собеседник: (поверх) нет, подождите, я про медкомиссию
```

## 5. Коммит и отказ

Прямое отражение инвариантов формальной модели.

| ситуация | состояние черновика | попадает в `turns`? |
|---|---|---|
| ответ доигран полностью | `Committed` | да, `is_partial=False`, `voiced_fraction=1.0` |
| перебили, аудио уже шло (FR-16) | `Committed` | **да**, `is_partial=True`, `voiced_fraction` = реальная доля |
| собеседник продолжил, аудио ещё не шло (FR-12) | `Dropped` | **нет**, никогда |

Инвариант `inv_dropped_never_committed` в [`dialogue.qnt`](../../formal/dialogue.qnt)
формально запрещает третьей строке попасть в память. Тест на это — обязателен, приёмка A-05.

Логика та же, что у человека: услышанное было сказано, неуслышанное — нет. Потерять
частично озвученный ответ так же плохо, как сохранить невысказанный: в первом случае
транскрипт разойдётся с тем, что реально прозвучало.

Отмена не требует межпоточной синхронизации — накопление идёт на event loop, и «отменить»
означает просто не вызвать `commit()`.

## 6. Буфер транскрипта

**Буфер — на всю сессию, а не на реплику.** Требование говорит «с самого начала разговора
пишем транскрибированный текст диалога» — то есть это скользящее окно по всему разговору,
которое живёт от `session.ready` до конца сессии. `reset_transcript()` вызывается только при
`session.reset`, но не по концу хода собеседника.

Проверка на здравый смысл: 5000 символов — это порядка сорока секунд плотной речи, а ход
завершается уже после 0.5 с тишины. Побуквенный буфер никогда бы до потолка не дорос, и
правило усечения не имело бы смысла.

Не путать с историей (`turns`) — это два разных представления одного разговора:

| | `turns` | `transcript_buffer` |
|---|---|---|
| что | структурированная история: роли, границы, перекрытия | сырой текст речи, склеенный подряд |
| зачем | LLM рассуждает о порядке и перекрытиях (FR-18, FR-19) | дешёвый инкрементальный prefill: дописывание в хвост |
| когда меняется | по завершении реплики | по мере поступления частичных транскриптов |

- Потолок `TRANSCRIPT_BUFFER_CHARS` = **5000** символов (FR-20).
- Усечение — **с головы**. Усечение с хвоста рушит KV-кэш llama-server, потому что общий
  префикс промпта перестаёт совпадать (см. [`llm.md` §6](./llm.md#6-раскладка-промпта-и-prefill)).
- Тайм-коды кусочков (`chunk_timings`) хранятся; **содержимое RAG-чанков в буфере не
  хранится** — оно избыточно и портит контекст.
- Буфер докладывается в prefill по мере роста, только дописыванием в конец. Замер: 8–23
  токена на обновление, ~60 мс независимо от длины.

## 7. Что нельзя делать

Перечислено потому, что каждый пункт — правдоподобная ошибка, ломающая систему тихо.

| нельзя | почему |
|---|---|
| останавливать запись в кольцо в каком-либо состоянии | FR-09; после `Speaking` не восстановить начало реплики собеседника |
| отдавать в воркер-поток сам буфер вместо `snapshot()` | гонка: поток читает объект, который мутирует loop |
| собирать историю по времени **прихода** событий, а не по таймингам аудио | при перекрытии порядок реплик получается неверным |
| усекать историю или транскрипт с хвоста | рушит KV-кэш, каждое обновление станет полным пересчётом |
| писать в `turns` из воркер-потока | всё состояние мутируется только на loop (`plan.md` §2) |
| считать длительность реплики агента по длине синтезированного файла | при уступке фактически отдано меньше; `voiced_fraction` станет враньём |
