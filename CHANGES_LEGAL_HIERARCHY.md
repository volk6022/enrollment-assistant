# Что изменено

## 1. Единый юридический корпус вместо одного PDF

Теперь базовая коллекция для ответа — `QDRANT_COLLECTION_LEGAL`.
В неё индексируются все `.docx` из каталога `LEGAL_DOCX_DIR` (по умолчанию `/data/npa/2025`).

Запуск индексации:

```bash
cd backend
python -m scripts.index_legal_corpus
```

Также поддержан прямой запуск файла `python scripts/index_legal_corpus.py`.

## 2. Учет юридической силы

Для каждого документа при индексации рассчитываются поля:

- `legal_force_code`
- `legal_force_name`
- `legal_force_level`

Поддерживаются уровни:

- Конституция РФ
- международные договоры РФ
- ФКЗ
- федеральные законы / кодексы
- законы субъектов РФ
- указы Президента РФ
- постановления Правительства РФ
- приказы министерств / ведомств
- локальные акты вуза / правила приема

## 3. Ранжирование ответов

Поиск теперь:

- ищет по единой юридической коллекции;
- учитывает редакцию документа;
- усиливает документы более высокой юридической силы для нормативных вопросов;
- усиливает локальные и ведомственные акты для процедурных вопросов (сроки, документы, этапы подачи);
- отдельно штрафует слишком общие акты для процедурных вопросов, если есть более прикладные документы;
- отфильтровывает узкоспециальные фрагменты, если вопрос общий и не про конкретную категорию поступающих.

## 4. Генерация LLM

Промпт обновлен:

- модель обязана учитывать юридическую иерархию;
- при конфликте брать вышестоящий акт;
- для procedural-вопросов не подменять конкретные правила приема общими законами и уставом;
- не переносить специальный порядок отдельной категории на всех поступающих;
- если конкретного перечня документов в найденных фрагментах нет, честно говорить об этом.

Добавлена post-check защита для ответов на вопросы о перечне документов: если модель уходит в узкую категорию без основания или опирается только на общие акты, ответ заменяется на осторожный диагностический.

## 5. Логика уточнений

Уточнения по слотам стали менее навязчивыми:

- вопрос про документы сам по себе больше не обязан сразу требовать статус поступающего;
- если уровень или форма уже названы в вопросе, лишнее уточнение не задается;
- организационные вопросы не запускают ненужные слоты.

## 6. Технические исправления

- исправлены переменные окружения коллекций в `docker-compose.yml`;
- backend теперь запускает `alembic upgrade head` автоматически;
- исправлена Alembic-ревизия `0003_add_study_form_to_dialog_sessions`;
- в `Dockerfile` добавлен `PYTHONPATH=/app`;
- скрипты индексации теперь корректно работают и через `python -m`, и через прямой запуск файла;
- уточняющие реплики ассистента сохраняются в БД;
- extractive-ответ стал короче и пригоднее для голосового озвучивания.


## v3 — снижение количества уточняющих вопросов

- ассистент сначала пытается найти и дать ответ, а не сразу спрашивать статус / уровень / форму;
- уточнение задается только если вопрос действительно нельзя безопасно закрыть без дополнительного слота;
- procedural и organizational вопросы теперь работают в режиме answer-first;
- при незавершенном уточнении новая самостоятельная реплика пользователя больше не запирается в старом pending-сценарии.


## v4: маршрутизация, реестр и контакты

- Добавлен файл `backend/app/knowledge.py` с ручной загрузкой реестра документов, загрузкой структурированных контактов, определением программы/темы и правилами исключения с учетом вопросов.
- Добавлены файлы `backend/config/document_registry.sample.json` и `backend/config/contacts.sample.json`.
- Индексирование теперь добавляет `doc_kind`, `program_scope`, `topic_scope` и надежные юридически значимые переопределения из реестра.
- RAG теперь применяет предварительную фильтрацию по теме и области действия программы перед оценкой.
- Организационные вопросы направляются к структурированным контактам, а не формируются на основе нормативных документов.
- Уточнения ограничены одним объединенным последующим запросом для рискованных вопросов («экзамены», «льготы», «право на участие») вместо нескольких последовательных запросов.
